# 数据字典

全部表使用 InnoDB、`utf8mb4_0900_ai_ci`。主键为 `BIGINT`，金额为 `DECIMAL(12,2)`，数量为 `DECIMAL(12,3)`，业务时间按 UTC 保存。

| 分组 | 表 | 说明 | 关键约束 |
| --- | --- | --- | --- |
| 组织 | `department` | 科室 | `code` 唯一、软停用 |
| 组织 | `ward` / `room` / `bed` | 病区、病房、床位 | 房间内床号唯一；床位状态 CHECK |
| 人员 | `staff` / `user_account` | 员工与登录账号 | 员工号、用户名唯一；BCrypt 哈希 |
| 权限 | `role` / `permission` | 角色与权限 | 编码唯一 |
| 权限 | `user_role` / `role_permission` | RBAC 关联 | 复合主键 |
| 患者 | `patient` | 患者主索引 | 患者号、证件号唯一 |
| 住院 | `admission` | 一次住院 | 状态、出入院时间 CHECK |
| 床位 | `bed_usage` | 床位占用历史 | 活跃生成列唯一；时间 CHECK |
| 变更 | `transfer_record` | 转床转科历史 | 新旧科室、床位、医生均可追溯 |
| 项目 | `medical_item` | 药品、检查、检验、治疗、护理、饮食、其他、床位费 | 类型、价格、库存、执行岗位与计费规则 CHECK |
| 项目 | `drug_profile` | 药品用量资料 | 每个药品最多一行；用量单位、库存换算和允许途径 |
| 医嘱 | `medical_order` | 医嘱头 | 住院、开立医生、编号和聚合状态；无频次及头级长期/临时字段 |
| 医嘱 | `order_item` | 医嘱项目及发生时快照 | 项目级长期/临时、处方剂量、给药方式、间隔和 PRN 每日上限；保存累计发药量及给药剂量 |
| 任务 | `medication_schedule` | 药品计划给药任务 | 项目+计划时间唯一；保存状态、完成时间及未执行原因 |
| 执行 | `execution_record` | 发药、给药、执行、未执行和冲正事实 | `request_no` 唯一；给药必须关联 `schedule_id`；实际数量与差异原因；禁止修改和删除 |
| 库存 | `drug_inventory_transaction` | 药品库存流水 | 入库、盘点及发退药来源；V7 强制 `after_quantity = before_quantity + quantity` |
| 押金 | `deposit_transaction` | 押金流水 | 冲正引用原流水、禁止删除 |
| 费用 | `charge_detail` | 费用流水 | 单价快照、执行来源、禁止删除 |
| 结算 | `settlement` | 出院结算 | 每次住院最多一张结算单；类别小计由收费明细实时聚合 |
| 风险 | `account_alert` | 欠费提醒 | 开放/已处理状态 |
| 模板 | `order_template` / `order_template_item` | 医嘱项目清单模板 | 创建者、启停状态、项目顺序和去重 |
| 编号 | `charge_detail.charge_no` | 费用流水号 | 由应用代码生成并由唯一约束防止重复 |
| 审计 | `audit_log` | 操作审计 | 操作者、角色、前后值、追踪号 |

当前完整结构由 Flyway V1–V7 定义，共 28 张应用表、7 个视图、4 个过程、18 个触发器。基础结构镜像 [`database/schema.sql`](../database/schema.sql) 与 V1 一致；索引、视图和过程分别镜像 V2–V4，`database/seed.sql` 合并 V5、V6，`database/inventory-balance-constraint.sql` 镜像 V7。Flyway 安装时另建历史表；不叠加旧版 `upgrade-v*.sql`。

## 索引依据

- 患者按证件号唯一定位，住院按患者/状态、科室/时间筛选。
- 床位按病区和状态筛选；有效床位占用通过生成列唯一索引解决并发冲突。
- 医嘱、执行、费用、押金按住院或业务对象与时间范围检索。
- 欠费提醒按状态/级别、审计日志按用户/时间查询。

性能演示使用 `EXPLAIN ANALYZE` 对比移除索引提示前后的访问行数、执行时间和访问类型，不在生产脚本中实际删除索引。


## 当前关键字段与约束

| 表 | 新增字段/约束 | 语义 |
| --- | --- | --- |
| `admission` | `active_patient_key` 唯一 | PENDING/IN_HOSPITAL/PENDING_DISCHARGE 状态下，同一患者只能有一条有效住院 |
| `bed_usage` | `active_bed_key`、`active_admission_key` 唯一 | 同一床位和同一次住院都只能保留一条未结束占用 |
| `order_item` | `item_type_snapshot`、`price_snapshot`、`order_type`、各累计量 | 主目录后续变更不改写既有医嘱事实；临时药品一次，长期药品定时或按需，实际给药次数从执行事实统计 |
| `medication_schedule` | `(order_item_id, scheduled_at)` 唯一、`status`、`completed_at` | 计划任务独立于实际执行；任务状态和完成结果可追踪 |
| `execution_record` | `phase`、`schedule_id`、`quantity_variance_reason`、`reversed_execution_id` 唯一 | 给药关联计划任务，记录实际数量及偏差原因；每条成功事实最多被冲正一次 |
| `deposit_transaction` | `request_no`、`original_transaction_id` 唯一 | 新押金请求去重；原押金最多一次完整冲正 |
| `charge_detail` | `department_id`、`unit_price_snapshot`、`original_charge_id` 唯一 | 保存发生科室和价格；反向费用沿用原快照且最多冲正一次 |
| `user_account` | `token_version` | 账号状态或密码变化后递增，JWT 必须匹配当前版本 |

数据库共有 18 个保护触发器。执行、费用、押金、库存、转科、结算和审计流水禁止 UPDATE/DELETE；床位历史禁止 DELETE，但允许转床或出院时写入结束时间。应用账号不应开放给普通用户直接写表。
