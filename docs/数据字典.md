# 数据字典

全部表使用 InnoDB、`utf8mb4_0900_ai_ci`。多数实体使用 `BIGINT` 主键；频次、途径字典使用字符串编码主键，关联表按关系使用复合主键。金额为 `DECIMAL(12,2)`，数量为 `DECIMAL(12,3)`，业务时间按 UTC 保存。

| 分组 | 表 | 说明 | 关键约束 |
| --- | --- | --- | --- |
| 组织 | `department` | 科室 | `code` 唯一、软停用 |
| 组织 | `ward` / `room` / `bed` | 病区、病房、床位 | 房间内床号唯一；床位状态 CHECK |
| 人员 | `staff` / `user_account` | 员工与登录账号 | 员工号、用户名唯一；BCrypt 哈希 |
| 权限 | `role` / `permission` | 角色与权限 | 编码唯一 |
| 权限 | `user_role` / `role_permission` | RBAC 关联 | 复合主键 |
| 患者 | `patient` | 患者主索引 | 患者号、证件号唯一 |
| 住院 | `admission` | 一次住院 | 状态、出入院时间 CHECK |
| 护理 | `nursing_observation` | 住院期间某一时刻的生命体征/意识观察 | 请求号全局唯一；同次住院同一观察时刻唯一；范围、住院时间窗和记录岗位校验；只追加 |
| 检查检验 | `inpatient_result` | 住院检查/检验执行产生的单项结果 | 绑定成功 `PERFORM` 执行；执行+检验项目+更正父项唯一；数值/文本至少一项；审核与更正只追加 |
| 诊断 | `diagnosis_catalog` | 诊断编码主数据 | 编码系统+编码唯一；软停用；作为住院诊断的受控来源 |
| 诊断 | `inpatient_diagnosis` | 一次住院中的诊断断言与状态 | 诊断编码/名称复合快照外键；每次住院最多一个有效主要诊断；状态只能有效→已解决/已排除 |
| 临床记录 | `inpatient_clinical_note` | 签署的入院评估、病程、病情变化和出院小结 | 同住院同类型自引用更正；入院评估/出院小结各一条原始记录；签署后只读 |
| 床位 | `bed_usage` | 床位占用历史 | 活跃生成列唯一；时间 CHECK |
| 变更 | `transfer_record` | 转床转科历史 | 新旧科室、床位、医生均可追溯 |
| 项目 | `medical_item` | 药品、检查、检验、治疗、护理、饮食、其他、床位费 | 类型、价格、库存、执行岗位与计费规则 CHECK |
| 项目 | `drug_profile` | 药品用量资料 | 每个药品最多一行；用量单位和库存换算；允许途径见关联表 |
| 项目 | `medication_route` | 住院药品给药途径字典 | 编码、名称和排序唯一；可软停用；发布后语义不可修改 |
| 项目 | `drug_profile_route` | 药品允许给药途径 | 药品与途径复合主键；每个药品的目录顺序唯一；双向外键 |
| 医嘱 | `medical_order` | 医嘱头 | 住院、开立医生、编号和聚合状态；无频次及头级长期/临时字段 |
| 医嘱 | `order_group` | 配液组 | 同一医嘱内组名、项目级类型和频次契约 |
| 医嘱 | `order_item` | 医嘱项目及发生时快照 | 项目级长期/临时、剂量、执行量、发药量和给药量；药品计划通过一对一子表关联 |
| 医嘱 | `medication_frequency` | 启用的药品给药频次参考数据 | 频次编码、最小间隔、一次性/规律属性；间隔形状 CHECK |
| 医嘱 | `medication_plan` | 药品医嘱项目的给药计划 | 以 `order_item_id` 为主键；频次引用、首次给药时间；不可更新/删除 |
| 执行 | `execution_record` | 发药、给药、执行、未执行和冲正事实 | `request_no` 唯一、环节 CHECK、禁止修改和删除 |
| 库存 | `drug_inventory_transaction` | 药品库存流水 | 前后数量和执行来源 |
| 押金 | `deposit_transaction` | 押金流水 | 冲正引用原流水、禁止删除 |
| 费用 | `charge_detail` | 费用流水 | 项目编码/名称/单位/类别/单价快照、执行来源、禁止删除 |
| 结算 | `settlement` / `settlement_detail` | 出院结算 | 每次住院最多一张结算单 |
| 风险 | `account_alert` | 欠费提醒 | 开放/已处理状态；开放住院生成列唯一 |
| 模板 | `order_template` / `order_template_item` | 医嘱项目清单模板 | 创建者、启停状态、项目顺序和去重 |
| 编号 | `charge_number_sequence` | 费用编号自增序列 | 仅用于安全分配费用流水号 |
| 审计 | `audit_log` | 操作审计 | 操作者、角色、前后值、追踪号 |

当前基础结构以 [`database/schema.sql`](../database/schema.sql) 为准，并与 Flyway 的 `V1__schema.sql` 逐字节一致。索引、视图、过程/触发器、演示种子数据、V6 完整性加固、V7 护理观察、V8 住院检查检验结果、V9 住院诊疗记录、V10 药品给药计划、V11 给药途径正规化、V12 PRN 清理、V13 费用类别快照和 V14 费用目录快照分别对应 `database/indexes.sql`、`views.sql`、`routines.sql`、`seed.sql`、`integrity-hardening.sql`、`nursing-observation.sql`、`inpatient-result.sql`、`inpatient-clinical-record.sql`、`medication-schedule.sql`、`medication-route-normalization.sql`、`remove-prn-frequency.sql`、`charge-category-snapshot.sql`、`charge-catalog-snapshot.sql`；不再叠加旧版 `upgrade-v*.sql`。

## 索引依据

- 患者按证件号唯一定位，住院按患者/状态、科室/时间筛选。
- 床位按病区和状态筛选；有效床位占用通过生成列唯一索引解决并发冲突。
- 医嘱、执行、费用、押金按住院或业务对象与时间范围检索。
- 欠费提醒按状态/级别、审计日志按用户/时间查询。

性能演示使用 `EXPLAIN ANALYZE` 对比移除索引提示前后的访问行数、执行时间和访问类型，不在生产脚本中实际删除索引。


## 当前关键字段与约束

| 表 | 新增字段/约束 | 语义 |
| --- | --- | --- |
| `admission` | `active_patient_key` 唯一 | PENDING/IN_HOSPITAL/PENDING_DISCHARGE 状态下，同一患者只能有一条有效住院 |
| `bed_usage` | `active_bed_key`、`active_admission_key` 唯一 | 同一床位和同一次住院都只能保留一条未结束占用 |
| `order_item` | `item_type_snapshot`、`price_snapshot`、`order_type`、各累计量 | 主目录后续变更不改写既有医嘱事实；药品计划通过 `medication_plan` 表达 |
| `execution_record` | `phase`、`batch_key`、`reversed_execution_id` 唯一 | 记录分环节执行；每条成功事实最多被冲正一次 |
| `deposit_transaction` | `request_no`、`original_transaction_id` 唯一 | 新押金请求去重；原押金最多一次完整冲正 |
| `charge_detail` | `item_code_snapshot`、`item_name_snapshot`、`unit_snapshot`、`item_type_snapshot`、`department_id`、`unit_price_snapshot`、`original_charge_id` 唯一 | 保存发生时项目编码、名称、单位、类别、科室和价格；正常费用沿用医嘱名称/单位并锁定产生时编码，手工费用匹配当时目录，反向费用沿用全部原费用快照且最多冲正一次 |
| `user_account` | `token_version` | 账号状态或密码变化后递增，JWT 必须匹配当前版本 |
| `order_group` / `order_item` | 复合外键 `group_id + medical_order_id` | 配液组只能被所属医嘱的项目引用 |
| `account_alert` | `open_admission_key` 唯一 | 同一住院最多一条 OPEN 欠费提醒 |
| `medical_item` / `order_item` | 库存模型与药品快照 CHECK | 药品必须有库存和剂量快照，非药品不得伪造库存/用量字段 |
| `execution_record` | 状态/数量/环节守卫 | 发药、给药、非药品执行使用正确单位和项目类型 |
| `drug_inventory_transaction` | 数量方向与前后数量 CHECK | 每条库存流水可按有符号数量对账 |
| `nursing_observation` | `request_no`、`(admission_id, observed_at)` 唯一 | 记录请求幂等；同一住院同一时刻不重复；记录人和观察时间由触发器校验 |
| `inpatient_result` | `result_no`、`(execution_id, analyte_code, amendment_parent_key)` 唯一；更正复合外键 | 结果来源锁定为住院检查/检验执行；更正父项必须属于同一执行和检验项目；结果值/文本和审核时间可追溯 |
| `diagnosis_catalog` / `inpatient_diagnosis` | 目录复合唯一、编码快照复合外键、有效诊断生成列唯一 | 诊断交易不能脱离受控目录；主数据名称变更不改写历史快照；一次住院只有一个有效主要诊断 |
| `inpatient_clinical_note` | `(amends_note_id, admission_id, note_type, amends_note_signed_at)` 复合外键；原始记录槽位唯一；父记录唯一更正 | 只允许同一次住院同一类型更正，且数据库验证更正不早于原签署时间；签署记录不可更新/删除；入院评估和出院小结不重复 |
| `medication_frequency` / `medication_plan` | 频次间隔 CHECK；频次语义 UPDATE 守卫；`medication_plan.order_item_id` 主键外键；计划追加守卫 | 药品新计划只引用启用频次；已引用频次可停用但语义不可变；一次性/规律由参考数据区分；首次给药时间落在医嘱时间窗内；实际次数不落库为目标值；PRN 频次已由 V12 移除 |
| `medication_route` / `drug_profile_route` | 途径编码/名称/排序唯一；药品—途径复合主键与双向外键；途径语义 UPDATE 守卫 | 多值允许途径满足 1NF；历史 CSV 迁移不允许静默丢值；新目录和新医嘱只能引用启用途径，医嘱保存发生时名称快照 |
| `charge_detail` | `item_code_snapshot`、`item_name_snapshot`、`unit_snapshot` 非空 CHECK；V14 来源触发器 | 费用查询、结算和审计显示发生时项目资料；目录后续改名、改编码或改单位不影响历史费用，冲正完整继承原快照 |

数据库共有 49 个保护触发器。执行、费用、押金、库存、转科、结算/结算明细、护理观察、检查检验结果、给药计划和已签署临床记录禁止 UPDATE/DELETE；诊断只允许从有效状态转为已解决/已排除。V6 另对住院归属、药品子类型、执行来源和库存来源做数据库级校验；V7 对护理观察的住院时间窗、记录岗位和追加不可篡改做数据库级校验；V8 对结果来源、住院归属、审核权限和更正关系做数据库级校验；V9 对诊断目录快照、主要诊断唯一性、诊疗人员科室、临床记录类型/时间和同住院更正关系做数据库级校验；V10 对计划子类型、频次引用、频次语义不可变、配液组频次、首次给药时间和药品执行时间窗做数据库级校验；V11 对历史途径迁移完整性及途径编码、名称、排序的发布后不可变做数据库级校验；V13 对费用类别快照、执行来源与类别一致性及冲正快照继承做数据库级校验；V14 对费用编码、名称、单位快照及冲正继承做数据库级校验。应用账号不应开放给普通用户直接写表。
