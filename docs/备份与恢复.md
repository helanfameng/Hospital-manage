# 备份与恢复方案

本文对应当前 V1–V7 迁移。备份目标必须与该版本的 `HOSPITAL_DB_URL` 一致；以下以业务库 `hospital_inpatient_main` 为例。备份不随源码目录保留。

## 备份

建议每天一次全量逻辑备份，业务高峰前后增加二进制日志归档。凭据通过 MySQL 登录配置或提示输入，不写入命令历史。示例中的 `D:/backup` 应替换为已经存在的备份目录，并将日期占位符替换为实际日期。

```powershell
mysqldump --single-transaction --routines --triggers --events `
  --set-gtid-purged=OFF --default-character-set=utf8mb4 `
  --result-file="D:/backup/hospital_inpatient_main_YYYYMMDD.sql" `
  -u hospital_backup -p hospital_inpatient_main
```

使用 `--result-file` 直接写出备份，避免 PowerShell 文本重定向改变编码。备份账号仅授予读取、视图、触发器和过程定义所需权限。备份保存到非应用磁盘，至少保留 7 个日备、4 个周备，并加密。

## 恢复演练

1. 创建空的 `hospital_inpatient_main_restore_test`，不要覆盖业务库或另一版本的测试库。
2. 使用 MySQL 客户端的 `SOURCE` 导入最近的全量备份：
   
   ```powershell
   mysql -u hospital_restore -p hospital_inpatient_main_restore_test --execute="SOURCE D:/backup/hospital_inpatient_main_YYYYMMDD.sql"
   ```

3. 必要时按时间点重放二进制日志。
4. 执行 `database/verify.sql`，核对 28 张应用表、7 个视图、4 个过程和 18 个触发器，确认 V7 库存平衡约束存在且违规流水数为 0。通过 Flyway 安装的数据库另有 `flyway_schema_history`；纯独立 SQL 安装不包含该表。
5. 对 Flyway 数据库，检查历史包含当前 V1–V7 且校验通过；旧开发链备份不能直接作为当前基线继续迁移。
6. 以恢复库为目标执行登录、住院详情、费用汇总和结算预检冒烟测试；端到端 `database/verified-workflow.sql` 仅在以 `_test` 结尾的独立测试库运行，并先初始化测试账号。
7. 记录 RPO、RTO、备份哈希和演练结果；演练库的清理由操作者在确认后执行。

目标：教学环境 RPO 不超过 24 小时，RTO 不超过 2 小时；这些是恢复目标，不代表当前已经完成演练。
