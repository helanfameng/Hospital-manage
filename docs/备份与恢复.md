# 备份与恢复方案

## 备份

建议每天一次全量逻辑备份，业务高峰前后增加二进制日志归档。凭据通过 MySQL 登录配置或安全提示输入，不写入命令历史。

```powershell
mysqldump --single-transaction --routines --triggers --events `
  --set-gtid-purged=OFF --default-character-set=utf8mb4 `
  -u hospital_backup -p hospital_inpatient > hospital_inpatient_YYYYMMDD.sql
```

备份账号仅授予读取、视图、触发器和过程定义所需权限。备份文件保存到非应用磁盘，至少保留 7 个日备、4 个周备，并加密。

## 恢复演练

1. 创建空的 `hospital_inpatient_restore_test`。
2. 导入最近全量备份。
3. 必要时按时间点重放二进制日志。
4. 执行 `database/verify.sql`，核对核心表行数、6 个视图、5 个过程和 20 个触发器。
5. 检查 `flyway_schema_history` 仅包含当前 V1–V5 且校验通过；旧 V6/V8/V13 备份不能直接作为当前基线库继续迁移。
6. 执行登录、住院详情、费用汇总和结算预检冒烟测试；在独立测试库运行 `database/verified-workflow.sql`。
7. 记录 RPO、RTO、备份哈希和演练结果后销毁测试库。

```powershell
mysql -u hospital_restore -p hospital_inpatient_restore_test < hospital_inpatient_YYYYMMDD.sql
```

目标：教学环境 RPO 不超过 24 小时，RTO 不超过 2 小时。
