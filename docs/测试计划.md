# 测试计划

## 自动化层次

- 单元测试：JWT、金额校验、核心服务与结算过程的处理。
- 前端测试：认证、路由权限、表单校验、医嘱编排、执行、费用、统计和审计等组件行为。
- SQL 镜像测试：六个独立安装 SQL 覆盖 Flyway V1–V7；V1–V4 分别对应，种子镜像合并 V5、V6，库存平衡约束镜像对应 V7。
- 条件集成测试：显式设置独立本机 `*_test` URL 和 `HOSPITAL_TEST_DB_ENABLED=true`；Flyway启动前检查目标库，测试真实提交/回滚，不用测试外层事务掩盖失败后的部分写入。
- 构建验收：后端 `mvnw.cmd test/package`，前端 `npm.cmd test/build`。

## 核心用例

| 场景 | 预期 |
| --- | --- |
| 正常入院 | 住院、床位历史、床位状态和押金同时成功 |
| 两人抢同一床位 | 一个成功，另一个被行锁/唯一约束拒绝 |
| 转入占用/维修床位 | 整体失败，原床位不变 |
| 药房发药 | 发药事实、库存流水、库存和费用同时更新；医嘱进入执行中 |
| 护士给药 | 未发药不能给药；临时一次完成，长期定时或按需滚动生成下一任务，不重复收费 |
| 给药任务 | 校验计划时间、PRN 间隔及每日上限；未来预览不可执行，数量差异及迟发需说明原因 |
| 入库与盘点 | 库存余额和追加流水在同一事务更新，V7 平衡约束拒绝前后数量不一致 |
| 非药品执行 | `PERFORM` 成功后按项目快照计费，临时项目完成 |
| 重复请求号 | 拒绝第二次执行，不重复收费 |
| 库存不足 | 执行、库存和费用全部不产生 |
| 退药 | 新增反向执行、库存归还和负向费用 |
| 费用超阈值 | 生成一条开放欠费提醒 |
| 未完成医嘱结算 | 预检失败且不释放床位 |
| 押金不足结算 | 阻止结算，提示补缴金额 |
| 正常结算 | 结算、收费明细实时分类汇总、退款、床位释放和出院状态同时成功 |
| 重复结算 | 唯一约束和过程校验共同拒绝 |
| 越权调用 | 返回 403 |
| 医生或护士查看当前住院 | 可查询列表和详情，不显示“办理入院”按钮 |
| 医生或护士直接访问入院登记地址 | 提示“当前账号无权办理入院”，阻止进入；已有合法页面不被替换 |
| 住院处或管理员查看当前住院 | 显示“办理入院”按钮并可正常进入登记页面 |
| 未登录访问入院登记地址 | 跳转登录页，不误提示为已登录用户的权限不足 |
| 删除关键流水 | 触发器拒绝 DELETE |

## 数据库课程验收

1. 检查 V1 定义的 28 张应用表的主键、外键、唯一、非空和 CHECK；V7 另补充库存流水平衡 CHECK。Flyway 运行后另有 `flyway_schema_history`。
2. 查询 7 个视图并与基础表手工抽样对账。
3. 检查 4 个存储过程和 18 个触发器；在专用测试库运行端到端 SQL 并验证事务回滚。
4. 使用两个并发连接申请同一床位。
5. 对住院、费用和押金查询运行 `EXPLAIN ANALYZE`。
6. 执行备份、还原到空测试库并核对行数和视图。

| 当时记录的验证场景 | 断言要点 |
| --- | --- |
| 多项目临时医嘱 | 部分执行不能完成；重复原请求/换请求号均不新增收费；全部完成才关闭 |
| 数量错误/库存不足 | 执行、费用和累计执行数量不产生部分记录 |
| 执行冲正 | 库存归还、费用归零、医嘱重开；不能重复冲正；原执行有多条费用也完整反向 |
| 押金退款/冲正 | 原请求唯一、冲正唯一、不能冲正反向记录、退款不超余额、押金总额不为负 |
| 出院/结算 | 草稿阻止出院；必须先申请；可撤回；退款快照准确、余额归零、床位释放、已结算账目禁止变更 |
| 转科 | 原医嘱未结束/未选新医生失败且保持旧床；正常转科同步归属，既有费用科室不变 |
| 数据范围 | 无权医生读不到患者/住院/执行/结算；护士访问本科室但不能发药或收款 |
| 认证安全 | 停用立即失效、重新启用不复活旧令牌；改密失效、重新登录成功；管理员API拒绝医生 |
| 竞争事务 | 同患者不同床、同床不同患者、同项目重复执行、同执行/押金重复冲正仅一个成功；补交与结算账目串行 |
| 提醒/审计/统计 | 低余额不能消除提醒，补交后自动消除；失败记录审计；维修床不计可用分母；药品净使用扣退回 |
