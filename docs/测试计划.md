# 测试计划

## 自动化层次

- 单元测试：JWT、金额校验、核心服务对存储过程参数与结果的处理。
- 前端测试：认证、路由权限、表单校验、医嘱编排、执行、费用、统计和审计等组件行为。
- SQL 镜像测试：十四个独立 SQL 与 Flyway V1–V14 逐字节一致。
- 条件集成测试：显式设置独立本机 `*_test` URL 和 `HOSPITAL_TEST_DB_ENABLED=true`；在 Flyway 启动前校验目标隔离性，并在类级前置检查中读取 `log_bin_trust_function_creators` 与失败的 Flyway 记录，测试真实提交/回滚，不用测试外层事务掩盖失败后的部分写入。前置检查只读，不自动改全局配置或迁移元数据。
- 构建验收：后端 `mvnw.cmd test/package`，前端 `npm.cmd test/build`。

## 核心用例

| 场景 | 预期 |
| --- | --- |
| 正常入院 | 住院、床位历史、床位状态和押金同时成功 |
| 两人抢同一床位 | 一个成功，另一个被行锁/唯一约束拒绝 |
| 转入占用/维修床位 | 整体失败，原床位不变 |
| 药房发药 | 发药事实、库存流水、库存和费用同时更新；医嘱进入执行中 |
| 护士给药 | 未发药不能给药；首次时间未到或未达到频次最小间隔不能给药；一次性药品一次完成，规律药品实际次数从流水统计，不重复收费 |
| 非药品执行 | `PERFORM` 成功后按项目快照计费，临时项目完成 |
| 重复请求号 | 拒绝第二次执行，不重复收费 |
| 库存不足 | 执行、库存和费用全部不产生 |
| 退药 | 新增反向执行、库存归还和负向费用 |
| 费用超阈值 | 生成一条开放欠费提醒 |
| 费用目录变更 | 历史费用仍显示产生时的编码、名称、单位和类别，不被当前目录重分类或改名 |
| 未完成医嘱结算 | 预检失败且不释放床位 |
| 押金不足结算 | 阻止结算，提示补缴金额 |
| 正常结算 | 结算、分类明细、退款、床位释放和出院状态同时成功 |
| 重复结算 | 唯一约束和过程校验共同拒绝 |
| 越权调用 | 返回 403 |
| 医生或护士查看当前住院 | 可查询列表和详情，不显示“办理入院”按钮 |
| 医生或护士直接访问入院登记地址 | 提示“当前账号无权办理入院”，阻止进入；已有合法页面不被替换 |
| 住院处或管理员查看当前住院 | 显示“办理入院”按钮并可正常进入登记页面 |
| 未登录访问入院登记地址 | 跳转登录页，不误提示为已登录用户的权限不足 |
| 删除关键流水 | 触发器拒绝 DELETE |
| 数据完整性加固 | 跨医嘱配液组、重复开放欠费提醒、错误执行环节、库存前后数量不等式均被数据库拒绝 |
| 药品给药计划 | 缺少计划、停用频次、长期+一次性、临时规律无结束时间、首次给药越过时间窗、配液组频次/首次时间不一致和计划 UPDATE/DELETE 均被拒绝；重复发药只增加库存批量，不增加实际给药次数 |
| 护理观察 | 超范围生命体征、无测量内容、血压不成对、住院外时间、非护士记录、重复观察时刻和 UPDATE/DELETE 均被拒绝 |
| 检查检验结果 | 非检查项目、非 `PERFORM`、跨住院执行、无结果值、重复检验项目、错误更正关系和 UPDATE/DELETE 均被拒绝 |
| 住院诊断 | 目录快照、跨科室诊断医生、重复有效诊断、重复主要诊断、非法状态迁移和 DELETE 均被拒绝 |
| 住院临床记录 | 非住院记录类型、错误时间、跨住院/跨类型更正、重复入院评估/出院小结和 UPDATE/DELETE 均被拒绝 |

## 数据库课程验收

1. 检查 V1 定义的 30 张应用表及 V7–V11 新增的 9 张住院业务表/主数据表的主键、外键、唯一、非空和 CHECK；Flyway V12 另检查频次模型已移除 PRN 字段，V13 检查费用类别快照和来源一致性，V14 检查费用目录快照和来源一致性；Flyway 运行后另有 `flyway_schema_history`。
2. 查询 7 个视图并与基础表手工抽样对账，重点核对 `v_medication_plan_progress` 的实际给药次数和下一次资格时间。
3. 检查 5 个存储过程和 49 个触发器；检查 V6–V14 跨表约束；在专用测试库运行端到端 SQL 并验证事务回滚。
4. 使用两个并发连接申请同一床位。
5. 对住院、费用和押金查询运行 `EXPLAIN ANALYZE`。
6. 执行备份、还原到空测试库并核对行数和视图。
